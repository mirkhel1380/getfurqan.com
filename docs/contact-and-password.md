# Contact page and password visibility

- `/contact.html` is linked directly in the desktop header, in the shared navigation drawer (including mobile), and in every footer. It shows `contact@getfurqan.online` as a mailto link. Publishing that address does not provision a mailbox.
- The contact form submits name, email, subject, message and interface language to the existing Al Furqan Supabase project. A success notice appears only after a server receipt. Messages appear under **Contact messages** in `/admin.html`, with pagination, unread filtering and read/unread actions. This is a private administrator inbox; there are no automatic email notifications and no third-party form service.
- The public submission capability is write-only. The private `af_contact.messages` table has RLS and no direct client grants. Public wrappers are SECURITY INVOKER; private functions use empty search paths. Inbox access and updates call the existing gate, requiring a live, verified, active administrator session. Anonymous submitters can never read any message. An authenticated submitter also passes the existing live-account gate.
- Server validation, a honeypot and per-address/global submission limits apply. A client-generated UUID is reused on retry after a lost response; the server checks identical content before returning the same receipt. Failed/timeout submissions retain text, while confirmed submissions clear it. No form message is saved to browser storage.
- The interface text is localized in all 13 supported interface languages. Message bodies, names and email addresses are excluded from interface translation. The About privacy paragraph describes stored contact data.
- The signup/signin field and password setup/reset fields have an accessible eye control. It changes only the input type, retains its value, updates its label/pressed state, never submits a form, and hides passwords again on mode changes, submit and page exit. It starts hidden without JavaScript, with the field masked by default.

Validation: `scripts/check-contact.mjs`, `scripts/check-password-visibility.mjs`, existing auth and locale checks. `backend/contact-security-check.sql` tests valid anonymous submission, retry idempotency, validation, rate limits, no direct reads, regular-user denial, administrator read state and revoked sessions in one rolled-back transaction, using synthetic data and sending no emails.

The security advisor reports the intentional policy-free private contact table alongside the existing private tables (clients have no table grants). The pre-existing optional leaked-password-protection warning remains: https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection
